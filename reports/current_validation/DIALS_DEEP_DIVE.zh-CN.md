# Ariadne 与 DIALS 的深度对照及下一步加速路线

日期：2026-10-31。基线：Ariadne `dedc4fa` 之后的工作分支；DIALS 3.30.1 未加载 Ariadne 覆盖层的已安装 C++ 代码。

## 本轮结论

斑点检测的速度与准确性不能只用一个任务排名。Ariadne 使用更复杂的校准背景和多尺度统计，在合成弱斑点测试上准确性更高，但 1024² 阈值阶段仍比 DIALS 约慢 4.8–5.0 倍。轮廓拟合的主路径已改成一个 C++ IRLS 内核，在相同权重和停止规则下与 DIALS 强度逐项一致，本机本轮实测约快 1.6 倍。

最强的准确性改进是把固定 deviance 阈值换成跨尺度标准化的超额统计：

$$
Z=\frac{\max(n-\mu,0)}
{\sqrt{\max(\mu+n_vv_r+W^2\sum v_b,.5)}} .
$$

其中 $W$ 是方形核宽度，$n_v$ 是有效像素数，$v_b$ 是环形背景传播方差。$W^2$ 项是对局部共享背景估计相关性的保守有效方差近似，不是精确的后验协方差。

最终测试集未参与阈值选择。标准化的默认参数为阈值 4、support sigma 0.5、连通域最小 4 像素、背景污染剪切 0 次。

## 斑点检测

训练集用于冻结参数，验证集用于检查稳定性，最终测试集未参与参数选择；发布前的基准复跑用于确认同一冻结规则的确定性。每个集合有 20 张 512² 合成图，每张 49 个已知斑点，混合背景、Poisson/Gaussian 读出噪声、不同斑点亮度和宽度。

| 最终测试算法 | F1 | Precision | Recall | 弱斑点 Recall | 强斑点 Recall |
|---|---:|---:|---:|---:|---:|
| 旧 Ariadne deviance | 0.7931 | 100.00% | 65.71% | 3.45% | 99.35% |
| 新 Ariadne standardized | **0.8518** | 96.51% | **76.22%** | **18.23%** | **99.78%** |

新统计量以少量额外假阳性换取了明显更高的总体与弱斑点召回，强斑点召回没有下降。验证集 F1 为 0.8475，与最终测试的 0.8518 接近，没有看到由最终集调参造成的跳升。

DIALS 在本对照中先经其 dispersion threshold，再使用与 Ariadne 相同的四连通域和最小尺寸过滤。DIALS 参数也在训练集上选择，最终设置为 `sigma_background=4`、`sigma_strong=4`、`min_size=5`。最终测试 F1 为 0.2532。这一结果说明在本合成强度分布下，阈值掩膜会产生大量小噪声连通域；它不等同于 DIALS 完整 `find_spots`、倒数空间过滤和指标化后的最终准确率。

速度方面，1024² 阈值阶段中位耗时为 Ariadne 25.3 ms、DIALS 约 5.1–5.3 ms。Ariadne 包含组件清理，DIALS 计时不包含后续过滤。剩余差距主要来自多尺度分数、全图背景统计和组件标记，而不是 Python 回调。

## 轮廓拟合

1/2/4/8 分量使用相同轮廓、固定背景、掩膜和 DIALS IRLS 权重。每种分量数执行 25 个随机案例；优化后的 Ariadne 结果为：

| 指标 | 结果 |
|---|---:|
| 最大强度差 | `1.02e-10` |
| 最大缩放 RMSE 差 | `8.76e-13` |
| Ariadne / DIALS 中位耗时比 | 0.611 |

即在该共同任务上，本轮 Ariadne 约为 DIALS 耗时的 61%，约快 1.64 倍；微基准会随机器负载变化，不应外推成完整积分流水线的固定倍数。C++ 内核在内部完成方差更新、法方程、秩检查和 Cholesky 协方差，避免每轮 Python/NumPy 边界往返。

在已知异方差高斯噪声下，每组 200 次试验的 95% 区间覆盖率为：

| 分量数 | Ariadne 分量/总量 | DIALS 分量/总量 |
|---:|---:|---:|
| 1 | 95.5% / 95.5% | 100% / 100% |
| 2 | 95.0% / 95.0% | 100% / 100% |
| 4 | 95.4% / 96.5% | 98.1% / 100% |

Ariadne 的覆盖接近名义 95%；DIALS `ProfileFitter` 的简化方差在本测试中偏保守。DIALS 的方差定义与 Ariadne 的完整条件协方差不同，不能把覆盖差异解释为谁的点估计更准确。

## 已完成的加速

1. C++ summed-area 内核只对通过 support/background 检查的候选像素评价多个尺度。
2. 默认背景剪切从 2 次降为 0 次；训练、验证和最终测试没有显示准确性损失，1024² 耗时在本轮约 25.3 ms，早期基准约为 38 ms。
3. 新增连通域最小尺寸过滤，在最终测试以 3.5% 假阳性换取 10.5 个百分点的总体 recall 提升。
4. 固定背景 IRLS 从 Python 循环改为单个 C++ 调用，保留 DIALS 相同的权重与停止规则。
5. 1/2/8 分量基准的 Ariadne/DIALS 耗时比从约 2.3/3.1/1.6 降到 0.63/0.55/0.46。
6. Metal/MLX float32 实测更快，但改变弱斑点像素判定，因此仍不设为默认。

## 继续加速的优先级

1. **合并背景积分通道。** 当前每种背景状态分别构建多个 summed-area 表。将计数、数据和方差积分放入一次缓存友好的双/四通道扫描，可减少内存带宽和临时分配。
2. **为全图循环加入有界线程池。** 行方向积分、背景与候选评分可以并行；组件并查集保持串行。只在超过约 25 万像素时启用，避免小图线程开销。
3. **区分候选发现与最终评分。** 用低成本单尺度统计排除绝大多数背景，仅对候选邻域计算三尺度标准化分数和背景方差。
4. **把组件特征放入 C++。** 在同一趟扫描中输出 size、峰值分数、质心和峰值-质心距离，便于后续过滤，不必在 Python 重复扫描。
5. **增加真实帧整链基准。** 下一步应使用公开旋转帧，对比 DIALS 和 Ariadne 的 strong spots、indexed fraction、predicted/observed 匹配、积分强度和最终 R 因子，而不把阈值阶段准确率当作整链性能。
6. **GPU 只做可验证的批量后端。** 需要 float64 或对边界像素做确定性 CPU 复核；否则 float32 的阈值差异不适合作为默认科学结果。
